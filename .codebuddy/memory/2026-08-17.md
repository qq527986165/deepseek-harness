# 2026-08-17

## pnpm install 报 "无法遍历路径，因为它包含不受信任的装入点" 根因定位与解决

**项目**: deepseek-harness（Windows 10 Pro 22H2 19045）

### 现象
- `pnpm install` 报 "The path cannot be traversed because it contains an untrusted mount point"，pnpm 版本切换也报相同错误（.tools/pnpm/11.7.0/bin/pnpm ENOENT）
- koffi@3.1.1 install 失败（无法加载 prebuilt → 尝试 CMake 编译 → 无 CMake），esbuild postinstall 失败，`.bin` 目录缺失

### 排查过程（全部有实证）
1. pnpm 版本切换问题：`.tools/pnpm/11.7.0` 是损坏挂载点 → `fsutil reparsepoint delete` 拆掉后，把完整解压的 `11.7.0_tmp_37552` 改名 `11.7.0` 修复（验证 pnpm --version = 11.7.0）
2. junction 遍历问题（核心根因）：
   - 新建 junction 后 Node/.NET/cmd 跟随遍历全部失败（readlink/lstat 正常，stat/readdir 失败，报 UNKNOWN / untrusted mount point）
   - 排除项：第三方杀毒驱动（仅 Windows 自带）、SymlinkEvaluation L2L（已启用）、SeChangeNotifyPrivilege（Enabled）、ACL 权限（正常）、盘符/卷类型（C、E 均失败）、AppLocker/本地安全策略、pnpm 链接损坏
   - .NET 原生 API 报错最精确：`The path cannot be traversed because it contains an untrusted mount point`
   - VBS 已启用（VirtualizationBasedSecurityStatus=2），HVCI 未配置（SecurityServicesRunning={0}）

### 最终根因
**Windows 完整性级别（Mandatory Integrity Level）机制**：普通终端 = Medium Integrity → Windows mount point 信任验证拒绝跟随 junction；**管理员终端 = High Integrity → 正常**。用户实测"以管理员身份运行 PowerShell 再 pnpm install"成功。

### 解决方案与关键结论
- **根因确认为 Windows "Redirection Trust Mitigation"**（Palo Alto Unit 42 研究）：junction 由 Medium Integrity 用户创建 → Level 1（低信任）；管理员/SYSTEM 创建 → Level 2（受信任）。进程跟随 junction 时按信任级别检查，拒绝时返回 `0xc00004be` "untrusted mount point"。
- 用户实测：管理员 PowerShell 跑 pnpm install/build 均成功（junction 由 High Integrity 创建）
- **重要修正**：光靠"管理员 install 一次"不够——pnpm build 在普通终端仍报 `Cannot find module node_modules\typescript\bin\tsc`（因为根 node_modules 的包都是 junction，普通进程读不了）。**日常 build/dev 也得管理员，或改用 hoisted**。
- 备选根治：`pnpm-workspace.yaml` 加 `nodeLinker: hoisted`（pnpm 11 起这类设置写 pnpm-workspace.yaml，非 .npmrc；`package-import-method=copy` 只影响文件复制方式，**不**避免 junction）。⚠️ 238 workspace 大仓切换有兼容风险，需管理员重装。
